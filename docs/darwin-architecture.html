Key Architectural Insights

1. XPC is the glue — not just IPC
XPC replaced raw Mach messaging as the standard daemon IPC in modern Darwin. launchd doesn't just start jobs — it brokers XPC connections between services. Panthera now has real XPC — a clean-room implementation (92 exports) with full object model, TLV wire-format serialization over Mach ports, bootstrap MIG protocol (check-in ID 402, look-up ID 404), and a connection layer with reply-port handshake. Two-process IPC verified in-guest.
2. The invisible daemon layer
Darwin has ~40-60 system daemons on a stock install. The most critical for a functional server: notifyd (notification hub), configd (network config), diskarbitrationd (disk management), securityd (keychain), opendirectoryd (user/group directory). These aren't optional — many Apple libraries silently degrade without them. With CF, XPC, and real launchd in place, building these from Apple source is finally unblocked.
3. CoreFoundation — the gateway dependency
CF-lite sits between libSystem and the daemon layer. Panthera has built CF from all 77 source files of CF-1153.18 — 1,562 exports, all 6 verification tests pass on live boot. The shared cache carries the full dependency chain: libc++abi → libc++ → ICU (8,890 exports) → objc4 (803 exports) → CoreFoundation. launchd now uses CF's real CFRunLoop and CFPropertyList code paths.
4. MIG — the forgotten code generator
MIG (Mach Interface Generator) takes .defs files and generates C stubs for Mach RPC. Panthera now has real MIG stubs — the bootstrap protocol (subsystem 400) uses MIG-generated code for check-in (ID 402) and look-up (ID 404). A full MIG pipeline for building kernel-interfacing tools (top, vm_stat, etc.) from source is the next step.
5. The dyld → libSystem → launchd bootstrap triangle
Every Darwin process starts: dyld loads → links libSystem.B.dylib → libSystem's constructor initializes sub-libraries → libdispatch connects to launchd. This chicken-and-egg is solved by Panthera's custom dyld which manually seeds early globals and emulates the constructor sequence — a significant engineering achievement.
6. Current position: Layer 9 of ~12
Layers 1-7 (done): kernel → boots → kexts → libSystem → dyld → GCD → XPC + libinfo.
Layer 8 (done): CoreFoundation (1,562 exports). Real XPC (92 exports). Real Apple launchd (runtime.c + core.c, 234KB, 385 exports). 19-dylib shared cache.
Layer 9 (current): Real plist/job bootstrap in launchd. Child process launch via posix_spawn.
Layers 10-12 (ahead): Daemon infrastructure (notifyd → configd → syslogd → securityd → sshd) → networking + multi-user → package management → distribution.
