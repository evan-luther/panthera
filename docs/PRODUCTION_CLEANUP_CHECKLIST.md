# Panthera Production Cleanup Checklist

## Goal

Make the repository understandable from a clean checkout, auditable by Apple engineers and OSS maintainers, and disciplined enough that source, patches, and generated outputs are easy to distinguish.

This checklist is based on the current worktree and read-only audit performed on 2026-04-03.

## 2026-05-02 Hygiene Pass

Current cleanup policy applied:

- `boot/efi/staging/` is generated boot media staging, not source.
- `boot/efi/loader/out/` is loader build output, not source.
- `kexts/OpenIOKit/build/` is generated kext output, not source.
- `artifacts/` is local evidence/log output, not source.
- compiled test binaries and test logs are local output; test `.c` and `.exp` sources remain tracked.

These paths should stay ignored and be regenerated by build/stage scripts. Release boot images, staged EFI trees, logs, and generated kext bundles belong in release artifacts or local `artifacts/`, not in normal source commits.

## Review Standard

If an Apple engineer opens the repository, they should be able to answer these questions quickly:

- Which files are imported from Apple OSS?
- Which of those files are patched locally?
- What is Panthera-authored?
- What is third-party?
- What is generated and should not be reviewed as source?
- Can the system be rebuilt from a clean checkout without hidden local state?

## Patch Documentation

### 2. Add a patch ledger for every modified upstream tree

Create:

- `docs/provenance/APPLE_PATCHES.md`

For each upstream tree with local edits, add:

- upstream name
- upstream version
- local modified files
- patch reason
- risk classification

Suggested categories:

- `bring-up tracing`
- `SDK / toolchain compatibility`
- `runtime workaround`
- `missing platform implementation`
- `temporary bootstrap hack`
- `intended long-term Panthera behavior`

Minimum initial sections:

- XNU
- launchd
- zsh
- `shell_cmds`

## Generated Artifact Policy

### 3. Separate source from output

Adopt this policy:

- source lives in `src/`, `boot/`, `rootfs/`, `tools/`, `kexts/OpenIOKit/local/`, and selected `userland/` build logic
- generated output should be rebuildable and not required for code review
- release artifacts should be produced by scripts, not treated as canonical source

Concrete actions:

- move generated/staged outputs behind build steps
- add `.gitignore` entries for object/stage trees
- if some generated outputs must remain tracked for now, mark them clearly as generated in path-local README files

### 4. Normalize non-Apple dependencies

Recommended production rule:

- if a dependency is optional, keep it out of the default assembly path

## Definition Of Done

Panthera is in production-grade provenance shape when:

- a clean checkout explains itself
- upstream Apple code and Panthera code are visibly separated
- local patches are enumerated and justified
- generated outputs are not confused with authored source
- third-party inputs are explicit and reproducible
- the default review path is source-first, not artifact-first
